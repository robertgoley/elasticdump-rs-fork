# L-808i: offline image build, crates fetched on the host (2026-11-02)

Problem: `scripts/build-image.sh` failed for the user with `could not resolve host index.crates.io`,
because `cargo build` in the builder container needed DNS and crates.io.

Change:
- `scripts/vendor-crates.sh` (new): `cargo vendor --locked --versioned-dirs` on the host into the
  gitignored `.vendor/crates` (whole workspace, including tools/edverify and tools/edgen), plus
  `.vendor/config.toml` (crates-io replaced by `/src/.vendor/crates`, `net.offline`). It stops with
  exit 2 and a clear message when the host has no cargo.
- `scripts/build-image.sh` runs it first; every Makefile `image*` target depends on a new `vendor`
  target, so the CI jobs that call `make image*` (security, nightly, release) work unchanged
  (ubuntu-24.04 runners ship cargo).
- `Dockerfile`: `COPY .vendor`, `CARGO_NET_OFFLINE=true`, and the cargo step is
  `RUN --network=none ... cargo build --locked --offline --release --config .vendor/config.toml`
  (fails clearly when .vendor/ is missing). The registry cache mount is gone (nothing is fetched).
- `.dockerignore` re-includes `.vendor/**` (e.g. cc's `src/target/` would be dropped by `**/target/`).
- README "Container image": offline-build paragraph (host needs cargo; proxy users only need host
  cargo network). No `--online` opt-out (not cheap: it needs a second build path).

Proof of offline:
- Both builds ran the cargo step under `RUN --network=none` and succeeded.
- Probe on the same dhi.io rust builder: under `RUN --network=none` only `lo` exists and
  `cargo search serde` fails (NET_BLOCKED); the next RUN without the flag reaches crates.io.
- No-cargo check: with cargo off PATH, vendor-crates.sh exits 2 with the message.

Results on the box:
- `scripts/build-image.sh --variant glibc`: localhost/elasticdump-rs:0.1.0 and :latest, 24.5 MB.
- `scripts/build-image.sh --variant alpine`: localhost/elasticdump-rs:0.1.0-alpine, 20.7 MB.
- `scripts/test-image.sh` dhi-static: 14 PASS, 0 FAIL; dhi-alpine: 15 PASS, 0 FAIL.
- `--platform both`: dry run only (vendoring is platform-independent: cargo vendor takes every
  platform's crates); not built under emulation here.
