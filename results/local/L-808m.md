# L-808m: edverify on the 1 GB smoke heap

## Root cause

The L-808l push seeded both corpora and all four Rust dump/restore operations
exited successfully. The final `edverify diff` used its default four concurrent
scrolls of 1000 docs. A continuation hit the JVM parent circuit breaker (HTTP 429).
The verifier neither retried that rejection nor cleared its contexts on error;
returning at the first failed task also aborted its siblings, leaving four scrolls.

## Changes

- L0 uses `edverify --size 100 --slices 1`; no heap, corpus, digest, tool paging or
  leak-check change. Other tiers and standalone edverify keep 1000 docs / 4 slices.
  Runner overrides `--verify-size` / `--verify-slices` accept positive integers;
  effective settings are recorded in result JSON and shown in dry runs.
- Every edverify HTTP request, including cleanup and `_count`, retries explicit
  HTTP 429 up to six times with 250/500/1000/2000/4000/4000 ms backoff. Request
  bodies remain identical. Other HTTP errors and ambiguous transport failures
  are not retried (a continuation response might have been lost after advancing).
- Track each returned ID before any fallible page processing. Drain all slice
  tasks, including delayed siblings after a failure or panic; then await scoped
  cleanup on success/error before `_count` or returning. Rotated IDs are deduped;
  wildcard/empty IDs are rejected, and no global clear is used.
- Cleanup 429s use the same bounded retry. Already-freed IDs (404) are harmless;
  other cleanup failures fail verification and retain the original scan error.
  edverify opens scrolls only, never PITs. A dead server/network or process kill
  cannot physically guarantee remote deletion; cleanup failure is never hidden.

## Regression coverage

13 real-HTTP/unit regressions: unchanged standalone defaults, backoff bounds,
rotated IDs and cleanup ordering, initial/continuation/count/cleanup 429 recovery,
exhaustion, non-429 failures, malformed pages, shard failures, delayed sibling
completion, task panic, count failure, cleanup failures on both scan outcomes,
already-freed IDs and rejection of a server-provided `_all` ID.

Python runner tests: 18 pass (the prior 16 seeder tests plus tier defaults and
configurable verification limits/positive-value checks).
