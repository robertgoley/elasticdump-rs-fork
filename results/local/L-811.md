# L-811: LOAD-017 leak check in the teardown of every load run

2026-11-01, `main` after D-2 (f96c434). Taken out of order: L-809 did not fit the usage check.

## Change
- `scripts/load/run.py`: new `leak_check(cl, work, before=, expected=, wait_s=15, contexts=True, allow_part=)`,
  returning `(leak, failures)`. It polls `_nodes/stats/indices/search` until `scroll_current` and
  `point_in_time_current` (OpenSearch) reach 0; on Elasticsearch, which has no PIT stat, `open_contexts`
  minus the scrolls (`other_open_contexts`) must reach 0 instead. It walks `work` for `.part` files
  (hidden staging files included, cluster dirs `it`/`it-*` skipped) and, with `before`, reports new
  non-system indices and new hidden indices outside `SYSTEM_INDEX_PREFIXES`.
- Every load script now calls it before teardown and fails the run on a leak: run.py, split.py
  (kill-case parts allowed, D-5), resume.py, faults.py, curves.py, compress.py and allocbench.py (these
  two had no leak check), nodecmp.py (contexts recorded only, because Node may leave scrolls open; Rust
  runs must leave none).
- `scripts/load/leakcheck_selftest.py`: offline stubs plus one small container per engine.
- scripts/load/README.md: the LOAD-017 paragraph.

## Findings
- The old run.py check used `glob("**/*.part*")`, which skips dotfiles, so it never saw the tool's hidden
  `.name.part-*` staging files; faults.py looked only at the top of `work`; curves/faults/resume/split
  checked scrolls but not PITs, and curves/split/nodecmp/resume did not fail on all leak kinds.
- Elasticsearch 7.17 has no `point_in_time_current` node stat (OpenSearch 2.19 does); `open_contexts`
  does count PIT readers, so PIT leaks are now caught on both.
- Not changed: memcheck.py (file-only, no cluster; its work dir is removed in `finally`) and the Rust IT
  suite (tests/it/api.rs already asserts open contexts per test index). TST-LOAD-017 also says "IT run";
  a per-IT-run teardown check is left as a follow-up for the lead.
