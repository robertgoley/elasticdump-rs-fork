# L-805a: slow-level and --overwrite leftover warnings

2026-11-01, user-approved fix-up of L-805 (compression levels) and L-648 / D-5 (leftovers).

- **Slow levels:** `--compressionLevel 9` with gzip and 19+ with zstd print a stderr warning (not an
  error; the level is still used, exit 0). Numbers come from the README compression table (L-805):
  gzip 9 about 120 MB/s per core against about 200 for gzip 6, and 3.5% larger with zlib-rs; zstd 19 about
  1.8 MB/s per core (1M docs took 9.5 minutes) against about 100 for zstd 9, whose file is about 30% larger.
  Defaults unchanged (gzip 6, zstd 3); `src/lib.rs` `slow_level_warning`.
- **--overwrite and leftovers:** the D-5 warning about a killed run's hidden files (`.name.part-PID-TS`,
  `.name.edrs-replaced-PID`) now adds, when `--overwrite` is given, "--overwrite replaces only the output
  itself; it does not remove these files". Behaviour unchanged: the files stay in place (D-5).
  `src/pipeline/file_sink.rs` `leftover_warning`. README: the kill -9 paragraph says so.
- `--help` for `--compressionLevel` mentions the warning.

Tests: unit `compression_default_tests::slow_levels_warn_others_do_not` (gzip 9, zstd 19/22 warn; gzip 1/6, zstd
3/9/18 do not; levels unchanged), `leftovers_of_finds_only_this_outputs_staging_and_moved_aside_files` (warning text
with and without --overwrite); contract `slow_compression_levels_warn_but_still_run` and
`overwrite_names_leftovers_and_keeps_them` (the leftover is named, the note is printed, the file is kept).
