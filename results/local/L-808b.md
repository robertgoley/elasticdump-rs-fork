# L-808b: glibc + mimalloc by default, default image on dhi.io static glibc, scripts/build-image.sh

User decision (2026-11-01): glibc builds use mimalloc by default and are the preferred build (cargo default, release
artifacts, docs, container image); musl/Alpine builds keep musl's own allocator; the Alpine image stays available as a
non-default variant. Box: shared 8-CPU / 15 GB VM, podman 5.4.2, toolchain 1.85.1, cargo-zigbuild with zig 0.13.

## 1. Allocator selection (Cargo.toml, src/main.rs)

- `[target.'cfg(all(target_os = "linux", target_env = "gnu"))'.dependencies] mimalloc` (non-optional on glibc Linux) and a
  `#[global_allocator]` cfg: mimalloc when the `mimalloc` feature is on, or on linux-gnu unless `system-allocator` or
  `jemalloc` is on. musl and other targets keep the system allocator unless a feature asks.
- Features: `jemalloc` (any target), `mimalloc` (force, any target, also musl), `system-allocator` (glibc malloc on
  linux-gnu; mimalloc's C code is still compiled there but not linked in). `jemalloc`+`mimalloc` and
  `system-allocator`+either are `compile_error!`s. Cargo.lock unchanged (mimalloc 0.1 / bundled mimalloc 3.3.2).

Cross-build matrix (`cargo zigbuild --release`, LTO off for speed; each binary ran a 20k-doc file-to-file round trip,
aarch64 under qemu-aarch64; allocator detected by `MIMALLOC_VERBOSE=1` "process init" and jemalloc symbols):

| Target | default | `system-allocator` | `jemalloc` | `mimalloc` |
|---|---|---|---|---|
| x86_64-unknown-linux-gnu | OK, mimalloc | OK, glibc malloc | OK, jemalloc | OK, mimalloc |
| aarch64-unknown-linux-gnu | OK, mimalloc | OK, glibc malloc | OK, jemalloc | OK, mimalloc |
| x86_64-unknown-linux-musl | OK, musl malloc | (n/a) | OK, jemalloc | OK, mimalloc |
| aarch64-unknown-linux-musl | OK, musl malloc | (n/a) | OK, jemalloc | OK, mimalloc |

All 15 runs: exit 0, 20000/20000 lines. The host `cargo build --release` (x86_64-unknown-linux-gnu) prints
`mimalloc: process init` with `MIMALLOC_VERBOSE=1`; the `--features system-allocator` build does not.

Release workflow (`.github/workflows/release.yml`): one matrix job; preferred `x86_64`/`aarch64-unknown-linux-gnu.2.28`
(zig glibc pin, Debian 10+ / RHEL 8+ / Ubuntu 20.04+; the job prints the highest `GLIBC_` symbol), plus the
unchanged `x86_64`/`aarch64-unknown-linux-musl`. Artifact names are unchanged (`elasticdump-rs-<target>.tar.gz`).
Checked locally: `cargo zigbuild --release --target x86_64-unknown-linux-gnu.2.28` → highest symbol `GLIBC_2.28`
(the plain-target builds above need `GLIBC_2.29`), mimalloc active.

Not considered: `static:20250419-glibc-debian13-fips` (FIPS variant, not needed), `static:*-musl-*` (not glibc).

**Pick: `dhi.io/static:20250419-glibc-debian13`.** It has everything the binary needs (glibc and `libgcc_s` for the
Rust/mimalloc binary, the CA bundle, numeric nonroot 65532, tzdata), is the smallest by 3–5×, has the fewest CVEs
(trivy 0 HIGH; grype's 5 High are in libc6 / libgcc-s1, which every glibc base carries), ships no shell or package
manager (less attack surface), and is published for amd64 and arm64. Cost: no shell, so (a) the final Dockerfile
stage is COPY-only (symlink and `/data` prepared in the builder, `COPY --chown=65532:65532`), (b)
`scripts/test-image.sh` inspects the rootfs through `podman export` instead of a shell, (c) wrapper scripts cannot run
inside the default image (the Alpine variant has bash). Builder: `dhi.io/rust:1.99.1-debian13-dev` (same Debian 13 /
glibc 2.41 as the runtime; amd64 + arm64).

grype High findings on the chosen base (all Debian `wont-fix` except CVE-2026-84243 `not-fixed`; trivy rates all
MEDIUM): CVE-2026-19499, CVE-2026-5435, CVE-2026-84243 (libc6 2.41-12+deb13u4+dhi1), CVE-2026-102010, CVE-2026-95619
(libgcc-s1 14.2.0-19+dhi5). **Consequence:** `make scan` (grype `--fail-on high`) fails on the new default image, as it
already did on every Debian base; the dhi.io Alpine image still scans clean. Flagged for the lead (accept as open, or
scan `base=dhi-alpine` in CI).

## 5. scripts/build-image.sh

`--variant glibc|alpine` (default glibc), `--platform linux/amd64|linux/arm64|both` (default host; `both` = podman
manifest list), `--tag REF` (repeatable), `--name REPO` (default `localhost/elasticdump-rs`), `--jobs N`, `--push`
(opt-in; uses only the existing `podman login`), `--dry-run`, `--help`. Default tags: `REPO:<ver>` + `REPO:latest`
(glibc), `REPO:<ver>-alpine` (alpine). Pins are read from the Makefile (`BUILDER_*`/`BASE_*`, `DHI_ALPINE_*`), so the
F-14 digest lint covers them. shellcheck 0.11.0: clean (also `scripts/test-image.sh`). Both variants built through it
(table above).
