# L-808l: scoped search-context loss and 1 GB load-smoke seeding

## Causes and changes

- L-618 deleted every scroll (and every OpenSearch PIT) on the shared test node.
  With four IT test threads this could destroy the scroll used by the ES7.10
  concurrency test. Its new loopback forwarding proxy captures the real context
  ID returned to this CLI and deletes only that ID before forwarding the response.
  The next real server request fails as before: exit 1, no committed output, and
  the appropriate keep-alive flag in the message. A separate live scroll/PIT must
  remain usable, and exactly one context deletion is asserted for each case.
  No global scroll/PIT deletion remains in tests/ or scripts/it/. The benchmark
  runner's existing all-scroll cleanup is on its exclusive private engine and is
  not part of the parallel IT suite (unchanged).
- The old L0 seeder used up to 5000 docs / roughly 8 MiB per bulk, which produced
  transient parent-breaker 429s during the adversarial edge corpus at a 1 GB heap.
  L0 now uses at most 500 docs / 1 MiB, keeping action/source pairs intact; an
  oversized single document is sent alone. One bulk is in flight, synchronously.
  Larger tiers and other seed_index callers keep their old default limits.
- Request-level and item-level 429s retry with bounded exponential backoff:
  six retries after the initial attempt, delays 0.25/0.5/1/2/4/4 seconds. Only
  rejected items are resent; exhaustion fails the run instead of counting the
  docs as invalid. Request-level 400 validation errors are still isolated by pair.
  Duplicate IDs start a fresh bulk, preserving last-wins order even when an earlier
  operation needs retry. The generator is closed/terminated on seed failure.
  Control requests (refresh/count/stats, etc.) also retry only explicit HTTP 429
  with the same bounded backoff; bulk seeding disables that outer retry so its
  request/item retry budget is not multiplied.
- The seed limits are recorded in the result JSON. The runner's 1024 MiB heap,
  data counts, reference-digest checks and leak checks are unchanged.
- CI runs the 16 cluster-free Python seeder tests before build/load. The touched
  paths include scripts/load, tools/edgen, tools/edverify and ci.yml, so generator
  and workflow edits cannot silently skip this check.
