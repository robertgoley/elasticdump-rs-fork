# Features to do (Node elasticdump parity)

What Node elasticdump does that this Rust version does not yet do, as of `main` at L-705 (2026-10-31). Data types and core dump, restore and copy are at parity, and per-direction credential flags (`--input-username`/`--output-username` and passwords) are done. None of the items below are in the current work queue; each needs an owner decision first (A10 backlog in [`project/handoff/HANDOFF-GROK-OPENCODE.md`](project/handoff/HANDOFF-GROK-OPENCODE.md)). Detail and effort estimates: [`project/plan/GAPS.md`](project/plan/GAPS.md). Effort: S under a day, M a few days, L a week or more.

## Small differences

| Area | Node | Rust | Effort | Note |
|---|---|---|---|---|
| `--pass` | Any encrypted key format | Encrypted PKCS#8 only | S | Legacy encrypted PEM (`Proc-Type: 4,ENCRYPTED`) needs `openssl pkcs8 -topk8` first; clear error with that hint. |
| `--fileSize` | Counts UTF-16 code units | Counts UTF-8 bytes | S | Same split points for ASCII; differ for non-ASCII data. |
| `--scroll-with-post` | GET unless set | Ignored, always POST | S | Matters only behind a proxy that blocks POST to `_search/scroll`. |
| `scrollRetryDelay` | Retries a partial page after a delay | Ignored; a partial page is a hard error | S | Rust fails safe. D-1 adds an opt-in flag for red indices. |
| `--force-os-version` | Forces the assumed OpenSearch version | Ignored; auto-detects | S | Only matters if a proxy hides `GET /`. |
| Type in URL path | Parses `/index/type` (ES 5 and 6) | Not parsed | S | Use `--output-index idx/type`. |
| Bulk HTTP method | PUT | POST | S | Only matters if a proxy allow-lists verbs. |
| Default User-Agent | `elasticdump` | Rust's own | S | Only matters where a WAF allow-lists the UA. |
| `--toLog` | Logs into a custom transport stream | Always stderr | S | Only relevant with custom transports. |
| `--maxSockets` | Unlimited by default | Also caps concurrent requests | – | Throughput tuning only. |
| `--throttleInterval` | 1 ms sleep per batch by default | 0 unless given | – | Faster. |
| `--intervalCap` and related | Effectively no-ops in Node 6.119+ | Enforced when set | – | Old scripts that set them now really rate-limit. |
| `--tlsAuth` | Cert flags apply only when set | Cert flags always apply | – | Safer by design. |
| `--offset` with scroll | Sends `from=` | Skips client-side | – | More correct. |
| `--fileSize`/`--maxRows` commit | Parts written as it goes | Staged, committed at the end | – | Safer; needs disk for the whole dump; leftovers are warned about. |
| `--format human` | `util.inspect` output | Pretty JSON | – | Cannot be combined with splitting. |
| `--esCompress` | Gzip responses only | Also gzips bulk bodies | – | Some proxies reject gzipped requests. |
| `--debug` log format | Node format | Different format | – | Log parsers may need changes. |
| `--heapSnapshot`, `--jsonLines`, `--support-big-int` | Node options | Accepted and ignored | – | Not applicable; big ints are always lossless. |

## Build and tooling

| Item | Note |
|---|---|
| `sftp://` inside the container images (**known issue in 1.0.0-beta1**, owner decision 2026-11-11: left as is for the beta) | OpenDAL's SFTP backend (`openssh` / `openssh-sftp-client` crates) runs the system OpenSSH `ssh` client; no image type ships it, and Dropbear's client is not compatible, so `sftp://` fails in every image while it works from the host binaries/archives with OpenSSH installed. Options: (a) add `openssh-client` to the images that have a package manager (dhi-debian, dhi-alpine, public, alpine; dhi-static has none, so it would need a copied client or stay without SFTP), at the cost of image size, CVE surface (new scan entries) and the executables baseline; (b) a pure-Rust SFTP backend (russh + russh-sftp) instead of the `ssh` subprocess, which also removes the subprocess from the behaviour profile but means a new OpenDAL service or our own `sftp` adapter and a fresh supply-chain review. Done when `sftp://` works in every image type and `scripts/opendal-tests/` (OpenSSH and Dropbear servers) passes against an image build. |
| Simplify the image build to one script plus one Dockerfile per build type (**owner request, 2026-11-03**) | Partly done in L-810c: `scripts/build-image.sh --type dhi-debian|dhi-static|dhi-alpine|public|alpine` builds every type (default `dhi-debian`, linux/amd64); still one multi-stage `Dockerfile` with pins in the Makefile. Before L-810c the image build is spread over the Makefile (`image`, `image-dhi-alpine`, `image-dhi-debian`, `image-public`, `image-alpine` plus pins and preflight), `scripts/build-image.sh`, `scripts/vendor-crates.sh` (crates fetched in a separate container, with network, cache-volume and userns workarounds) and one multi-stage `Dockerfile` switched by build args and `--target`. Replace it with a single bash `build-image.sh <type>` that runs `podman build -f Dockerfile.<type>` (for example `Dockerfile.dhi-static`, `Dockerfile.dhi-debian`, `Dockerfile.dhi-alpine`, `Dockerfile.public`, `Dockerfile.alpine`), each a self-contained, readable Dockerfile with its own pinned base images. Keep: a podman-only host (no host Rust), the dhi.io login check with a clear message, `--tag`/`--platform`/`--push`, image tags as today. Decide whether crates are fetched inside the build (a builder stage with network, cached with `RUN --mount=type=cache`) instead of the separate vendoring container, which would remove `vendor-crates.sh` and its DNS/userns workarounds; if offline builds stay a requirement, keep vendoring as an optional `--offline` mode. Drop the Makefile image targets (or make them one-line calls to the script), move pins out of the Makefile into the Dockerfiles, and update `scripts/lint-hygiene.sh` F-14, CI (`ci.yml`/`release.yml` image jobs), `scripts/test-image.sh`, `docker/image-binaries.*.txt`, the README build section and the handoff docs. Done when every current image builds from a fresh clone on Ubuntu with only podman and a dhi.io login, and the image tests pass. |
| searchdump-multi in-process (threads instead of child processes) (**owner wishlist, 2026-11-07**) | Today `searchdump-multi` starts one `searchdump` process per index and item type. Running them as tasks in one process would share one memory budget and HTTP connection pool, give one progress view and no binary lookup, and could make a busybox-style single binary possible. Startup cost is not the reason (runs are I/O-bound). Needs the main tool's process-wide state (parsed argv, secrets, memory plan, signal handling, global logging) moved into a per-run context first, and a panic/OOM in one index must not take down the rest (catch_unwind per task, per-task memory caps). Do it after real-cluster testing of the current version. |

## Roadmap: 1.1 release (performance and robustness)

Added 2026-11-11 from the post-beta1 code review. Measure each change with the perf suite (A/B against the v1.0.0-beta1 baseline) before and after. Effort: S under a day, M a few days.

| # | Item | Where | Why | Expected impact | Effort | Status |
|---|---|---|---|---|---|---|
| 1.1-1 | Stop refreshing after every bulk batch: refresh at most every few seconds plus once at the end; keep per-batch refresh as an opt-in for Node parity | `src/pipeline/bulk.rs` (~878, `refresh()` ~1102) | At L0 a restore takes ~5.6 s wall for ~0.86 s CPU, so it is waiting on the cluster; single restore 17.8k docs/s vs 62k with multi `--parallel 8`. Add an A/B perf case with `--noRefresh` | 2-4x on restore and copy | S | in progress (release/1.1): code + unit/contract tests committed, not yet compiled (suite running); A/B pending |
| 1.1-2 | Restore with no output index must not `POST /_refresh` the whole cluster; refresh only the indices the batch wrote | `src/pipeline/bulk.rs` (~1107) | Refreshing every index after every batch hurts production clusters (bug) | correctness and cluster load | S | in progress (release/1.1): code + unit/contract tests committed, not yet compiled (suite running); A/B pending |
| 1.1-3 | Add `"sort":["_doc"]` to the default scroll body when the user's search body has no sort; check Node output-order parity | `src/retrieval/search_body.rs` (~11) | Elasticsearch recommends `_doc` sort as the cheapest scroll | moderate on dumps, more on large indices | S | planned |
